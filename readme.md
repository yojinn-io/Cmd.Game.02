## 基本操作の説明について
基本的な操作方法については、オプション内の「Readme」を参照してください。ここでは主にコード構造と実装内容について説明します。

## 
### 1. コンソール上でのUI制御と描画について
本ゲームでは、コンソール上でのUI制御や描画を行っています。これはPCゲーム制作と基本的なロジックは同じですが、違いとしてはコンソール上で対応する文字を手動で描画している点です。

ANSIエスケープコードを利用することで、カーソルの移動や出力位置の制御を自由に行えます。詳細なコマンドは以下のリンクを参照してください：
[ANSI 説明](https://gist.github.com/fnky/458719343aabd01cfb17a3a4f7296797)

※ANSIコードはクロスプラットフォーム対応で、Linux環境でも使用可能です。一方、Windowsには専用のコンソール関数もあり、より高速に描画を更新できます。

### 2. イベント駆動モデルの採用
ゲーム全体はイベント駆動方式を採用しており、各機能モジュールを明確に分離しています。
各シーンのデータはSessionに保存され、関数間のデータ共有はContextを通じて行われます。

処理の流れは一般的な分層構造で構成されています：
初期化 → プレイヤー入力 → ゲーム更新 → 描画 → リソース解放

### 3. MNKゲームの勝敗判定
勝敗判定には、汎用的なMNK（M,N,K）ゲームのロジックを採用しています。これにより、任意のMNK形式のゲームに対応可能です。
参考として、GitHubには多くのオープンソースプロジェクトがあります。中でも分離設計が明確な下記プロジェクトは特に参考になります：
[/jstriedinger/mnk-game](https://github.com/jstriedinger/mnk-game)

### 4. ゲームAIについて
AI実装は本プロジェクトでもっとも複雑で難しい部分でした。Minimaxアルゴリズムにα-β枝刈りを組み合わせ、評価表によるスコアリングでAIの判断を行っています。

ただし、現段階ではバグや最適化の面で満足のいく仕上がりには至っておらず、今後の改善余地があります。なお、プレイヤー同士の対戦については問題なく動作しています。
特にAIの判断アルゴリズムのチューニングに多くの時間を要しました。
